## 一、当前问题分析（基于代码实测，非臆测）

### 1.1 现有信息架构（IA）
当前站点是**零依赖 Node SSG**，内容完全由 `data/*.json` 驱动，渲染逻辑集中在 `src/lib/content.js`，URL 由 `type` 字段路由（`urlFor` / `linkUrl`）。

```
首页 (/)
├── 目的地/国家 (/countries)            ← 目录页
│   └── 国家页 (/china/、/japan/…)
│       └── 城市页 (/china/beijing/、/japan/tokyo/…)
│           ├── 景点攻略   (/…/attractions/{slug})
│           ├── 路线规划   (/…/routes/{slug})
│           ├── 实用攻略   (/…/guides/{slug})
│           ├── 最佳时间   (/…/best-time)
│           └── 完整路书   (/…/route-plan/{slug})   ← 旗舰 JSON 驱动
├── 城市 (/cities) / 景点 (/attractions) / 路线 (/routes) / 指南 (/guides)  ← 全局目录页
└── 静态长页 (/about /services /contact /privacy /terms /sitemap-page
            + 北京 normal/budget 手工 HTML，游离于数据模型之外)
```

**页面类型现状（8 种 + 1 类遗留）**
| 类型 | type 值 | 来源 | 状态 |
|---|---|---|---|
| 首页 | home | data/home.json | ✅ 数据驱动 |
| 国家页 | country | data/countries | ✅ 数据驱动 |
| 城市页 | city | data/cities | ✅ 数据驱动（子内容自动汇总） |
| 景点 | attraction | data/attractions | ✅ 数据驱动（blocks） |
| 路线 | route | data/routes | ✅ 数据驱动（blocks） |
| 攻略 | guide | data/guides | ✅ 数据驱动（blocks） |
| 最佳时间 | best-time | data/best-times | ✅ 数据驱动 |
| 路线规划 | route-plan | data/route-plans | ✅ JSON 驱动 12 模块 |
| 遗留长页 | — | src/static/china/beijing/*.html | ⚠️ **脱离数据模型，自带 footer** |

### 1.2 页面之间关系
- **正向推导良好**：`buildCitySections / buildCountrySections / buildIndexSections / buildHomeSections` 全部从 `entities` 数组**自动派生**，新增一个 city/route/guide 的 JSON 即自动出现在对应城市页、国家页、目录页、首页——**零模板改动即可扩展**。这是 v2.0 必须保留的核心架构资产。
- **断点**：北京 normal/budget 两份手工 HTML 不走这条推导链，其 footer 与全局 `layout.html` 的 footer 是**两套不同内容**，造成站点底部信息不一致。

| P10 | **设计资产不可复用** | 无统一 design tokens；route-plan 内联样式无法被其他页复用 | 每加一类页就重造轮子 |

## 二、v2.0 产品定位

**一句话定位**：一个**国际化、杂志级质感**的旅行规划平台——以**官方高质量攻略为内核**，以**用户内容生态为增长引擎**，可平滑扩展到 100+ 城市、多国。

**设计关键词**（来自验收要求）：高级 · 简洁 · 国际化 · 杂志感 · 旅行感 · 探索感。
**明确不要**：后台管理感 · 信息堆砌感 · 大量卡片堆叠 · 过多边框 · 过度颜色。

**三层产品模型**
1. **内核层（官方内容）**：专业、可信、SEO 友好，承担搜索流量与品牌信任。
2. **生态层（用户内容·v2.0 起步仅数据结构）**：游记 / 相册 / 路线分享 / 体验评价，承载社区与留存。
3. **平台层（设计系统 + 扩展框架）**：统一视觉、统一组件、type 路由即扩展点，保证 100+ 城市零模板改动上线。

## 三、内容生态架构

### 3.1 官方内容（保留并扩充）
```
官方内容
├── City Guide        城市指南      → type: city (+ 派生子页)
├── Route Plan        深度路线规划  → type: route-plan   (现有，强化)
├── Budget Plan       预算旅行方案  → type: budget       (由遗留 beijing budget 升级为数据驱动)
└── Seasonal Guide    季节攻略      → type: seasonal     (新增)
```

### 3.2 用户内容（v2.0 第一阶段：仅数据结构，不实现功能）
```
用户内容
├── Traveler Note     用户游记      → type: note
├── Photo Diary       图片记录      → type: photo
├── Route Share       用户路线分享  → type: share
└── Experience Review 体验评价      → type: review
```

### 3.3 统一内容元数据（所有 UGC 及可选官方内容携带）
任何 UGC 实体在现有字段之上，**追加**以下标准块（阶段一仅定义，不渲染功能）：

```jsonc
"authorship": {
  "author": "旅行者昵称",
  "avatar": "/assets/img/avatars/xxx.jpg",   // 或外链
  "publishDate": "2026-08-15",
  "updateDate": "2026-08-20"
},
"engagement": {
  "likes": 0,
  "saves": 0,
  "comments": 0
},
"tags": ["东京","美食","免费景点","亲子"]
```

> 阶段一约束：上述字段**存在即可**，页面不实现点赞/收藏/评论交互；菜单与列表页可先以 `publishDate`/`author` 做静态展示。功能交互（P3+）再接后端或静态 JSON。

### 3.4 内容关系图（v2.0 目标 IA）
```
首页
└── 国家 → 城市
         ├── 官方：City Guide / Route Plan / Budget Plan / Seasonal Guide
```

## 五、UI 设计方向

### 5.1 对标与气质
- **Lonely Planet / National Geographic Travel**：杂志感、大图叙事、编辑级排版。
- **Airbnb Experiences / Booking Guide**：干净留白、卡片克制、信任感。
- 气质词落地：**探索感**用大图 hero + 地理感衬线标题；**高级感**用充足留白 + 单一主色 + 精致分割线；**国际化**用语义清晰、不堆术语。

### 5.2 反模式清单（v2.0 禁止）
- ❌ 后台管理感（灰底表格 + 边框地狱）
- ❌ 信息堆砌（一屏塞满色块）
- ❌ 大量卡片堆叠（无节奏地 grid 一排排）
- ❌ 过多边框（用留白和底色分区，而非 1px 线）
- ❌ 过度颜色（全站主色 ≤ 2，辅以 1 个强调金/赭）

### 5.3 统一视觉提案（解决 P1 双系统）
- **单一主色**：建议从现有两稿收敛为**一个旅行绿 `#2E7D32` 体系**（route-plan 已验证耐看），暖红降级为"警示/特价"点缀色，不再作主色。
- **单一字体气质**：标题用衬线（编辑感），正文用无衬线（可读性），全站统一，不再出现两套 `font-family`。
- **统一容器宽度**：现有 `min(920px,100%)` 合理，全站沿用。

## 六、移动端设计规范（375px iPhone 优先）

1. **标题断词**
   ```css
   h1,h2,h3 { word-break: keep-all; text-wrap: balance; }
   /* 中文标题禁止在词中断行；多行标题视觉均衡 */
   ```
2. **字号 / 行高 / 字距**
   - H1 移动端 ≤ 30px，line-height 1.25，letter-spacing 0（中文勿加字距，西文可 +0.2px）。
   - 正文 16px / line-height 1.7。
3. **卡片优化（解决 P4 长卡片）**
   - 时间轴默认只显示：上午 → 浅草寺；点「查看详情 ↓」再展开 最佳时间/摄影点/预约/Tips。
   - 用 **Accordion / Tab** 替代整页无限长卡片；单日 8 item 折叠为"上午/下午/晚间"三段可展开。
   - 表格在 375px 用 `overflow-x:auto` 容器（已在 18.8 为 route-plan 表格加 `.table-scroll`，需提升为全局 design-system 规则）。

## 八、Design System v2.0 规划（解决 P1/P10）

**目标**：不再"每页自己设计"。建立 `src/design-system/`，所有页面统一消费。

### 8.1 目录结构
```
src/design-system/
├── tokens.css        # 颜色 / 字体 / 间距 / 圆角 / 阴影 / 断点（唯一 :root）
├── base.css          # reset / body / 标题 / 链接 / 排版规则
├── layout.css        # 容器宽度 / 栅格 / 响应式断点
├── components/
│   ├── header.css    # 顶部导航（替代现有 .topnav）
│   ├── footer.css    # 新 Footer
│   ├── card.css      # 通用卡片（去边框、靠底色分区）
│   ├── button.css    # 主/次按钮
│   ├── timeline.css  # 时间轴（含移动端 Accordion）
│   ├── table.css     # 表格（含 .table-scroll 横向滚动）
│   ├── badge.css     # 标签/徽章
│   └── accordion.css # 折叠组件
└── mobile.css        # 375px 规则（keep-all / balance / 单列）
```

### 8.2 落地方式（零新增依赖、可纳入现有 SSG）
- 在 `build.js` 复制 `src/assets` 之前，先将 `src/design-system/*.css` 与 `components/*.css` **拼接**为单一 `src/assets/css/style.css`（纯字符串 concat，无需构建工具）。
- `layout.html` 仍只 `<link rel="stylesheet" href="/assets/css/style.css">`，全局生效。
- **删除** `body-route-plan.html` 内联 `<style>`，其专属样式（cover/timeline/eco-banner 等）迁移进 `components/`，与全局 token 对齐。
- 所有模板改用同一套 class 命名（BEM 风格），杜绝页面级私有样式。

### 8.3 Tokens 草案（收敛双系统）
```css
:root{
  --brand:#2E7D32;            /* 旅行绿，唯一主色 */
  --brand-dark:#1B5E20;
  --accent:#F9A825;           /* 强调金，仅点缀 */
  --warn:#8b1e18;             /* 特价/警示，降级使用 */
  --ink:#2B2B2B; --ink-light:#5A5A5A;
  --paper:#FFFDF8; --bg:#FAF6F0; --line:#E7E0D4;
  --r-sm:8px; --r-lg:16px; --r-pill:999px;
  --shadow:0 14px 40px rgba(40,30,20,.10);
  --serif:"Noto Serif SC",Georgia,serif;       /* 标题 */
  --sans:-apple-system,"Noto Sans SC",sans-serif;/* 正文 */
  --container:min(960px,100%);
}
```

## 十、附：route-plan 标题逻辑修复建议（P3 即时可改，待确认）

**现状（错误）**
- 模板 `body-route-plan.html:166`：`<h2>版本核心调整</h2><p>vs Standard Edition</p>`
- 数据 `changes.desc`：「相比标准舒适版，经济版在…做减法」

**修复（符合用户真实认知）**
- 标题改为：**「本路线设计理念」**
- 副标改为：`Why this plan works`
- 数据字段 `changes` 重命名为 `designPhilosophy`（或 `strategy`），`desc` 改写为**正向陈述**而非"对比不存在的版本"：
  ```
  为什么这样规划？
  · 控制预算——把每一笔花在核心地标
  · 优先免费景点——多数体验零门票
  · 地铁 + 步行为主——省交通费也更深入
  · 减少无效消费——避开 tourist trap
  · 保留东京核心体验——经典一个不落
  ```
- 备选标题方案（同样合规）：「经济版旅行策略」+「相比普通自由行，本方案重点优化：① 时间利用率 ② 交通成本 ③ 景点选择 ④ 餐饮安排」。

> 此修复**仅改标题文案与字段命名**，不动 URL / type / schema / 东京 route-plan 其他内容，符合全部约束。是否执行待 v2.0 设计确认后进入 P0-3。

## 十一、结论
当前站点**架构骨架优秀**（数据驱动、type 路由、自动派生、可扩展 100+ 城市），最大短板在**表现层**：双视觉系统、博客式 Footer、route-plan 标题逻辑硬伤、移动端长卡片与断词。v2.0 应**保留并放大架构资产**，以统一 Design System 收口视觉，以"官方内核 + UGC 生态"双轮扩展内容，分阶段、零破坏地演进。本评估为只读产物，未改动任何代码/模板/数据。
