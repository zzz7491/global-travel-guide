# 第一部分：当前问题分析

## 1.1 Phase 0 现状盘点（基于代码与渲染产物实测）

**首页现状**（`public/index.html` 实测结构）：
```
<nav.topnav>（5 项药丸导航）
<main>
  <h1>Global Travel Guide</h1>
  <p.lead>全球旅行攻略与自由行路线指南 —— …</p>
  <section>世界目的地 → .cards 纯文字卡（中国/日本/北京/东京混排）
  <section>精选路线   → .cards 纯文字卡（5 条路线）
  <section>最佳旅行时间 → .cards 纯文字卡（北京/东京）
  <section>旅行指南   → 单卡（/guides）
</main>
<footer.site-footer>（v2.0 国际版）
```
- **无独立 Hero 区**：视觉背景来自 `style.css` 的 `body` 背景 `linear-gradient(rgba(250,246,240,.9),…) + var(--hero-image)`——90% 不透明米色叠加把大图几乎盖住，**首屏实际是米色 + 文字**，无大图冲击。
- 模板：首页复用 `body-listing.html`（与目录页同一模板），`buildHomeSections`（`content.js:223`）自动派生 4 区块。
- 卡片 `.card` 只有 `<strong>`+`<span>` 纯文字，**全站卡片无图**。

**城市页现状**（`public/japan/tokyo/index.html` 实测）：
- `h1 东京` + lead + 5 组文字卡（景点攻略/路线规划/实用攻略/最佳旅行时间/完整路书），由 `buildCitySections`（`content.js:154`）按 `country+city` 自动派生——**机制良好，视觉未展开**。

**数据模型**（`data/` 实测）：
- 7 类型实体：country / city / attraction / route / guide / best-time / route-plan；`urlFor/linkUrl`（`content.js:16,32`）type 路由清晰。
- city 已有可选字段 `nameEn/continent/language/currency/timezone/related`（仅东京完整填写；北京缺）。
- route-plan（东京 economy）已是 12 模块旗舰 JSON：`days/seasonNote/suitableFor/travelTone/designPhilosophy/overview/ticketTiers/accommodation/budgetTiers/budgetTable/dailySummary/alternatives/foodDetail/transitDetail/charts/savingTips/reminders/packing`——**跨城市可复用，是「规划平台」的弹药库**。
- 北京 normal/budget 仍是游离静态页（`src/static/china/beijing/*.html`），未入数据模型（P1 吸收）。

**Design System**（`src/design-system/`）：
- tokens.css（颜色/字体/间距/圆角/阴影）/ components.css（topnav/footer/table-scroll/btn）/ responsive.css（keep-all/balance/移动端 footer/overflow）已就位。
- **组件缺口**：无 hero / 卡片 / 统计 / 区块头 / 徽标 / 空态等视觉组件——本设计第五部分补齐。

## 1.2 首页问题清单（用户首次访问 3 秒测试）

| # | 问题 | 3 秒内用户能否回答 | 实证 |
|---|---|---|---|
| P1 | **首屏无「旅行感」** | ❌ 这是旅游网站吗？ | 米色底 + 药丸导航 + 标题段，无大图 hero，更像文档/目录站 |
| P2 | **H1 是品牌名而非价值主张** | ❌ 它能为我做什么？ | `<h1>Global Travel Guide</h1>`；lead 为陈述句而非行动句 |
| P3 | **无 CTA** | ❌ 我该点哪里？ | 首页无「开始规划 / 探索目的地」按钮 |
| P4 | **国家/城市混排** | ❌ 有哪些国家？ | 「世界目的地」把中国/日本 与 北京/东京 同一卡片网格混排，层级不清 |
| P5 | **无节奏、纯文字卡** | ⚠️ 有哪些路线？ | 路线/时间区块均为 `.card` 文字列表，无图无节奏，信息密度低 |
| P6 | **空区块** | ⚠️ 结构单薄 | 「旅行指南」仅 1 张卡；无「为什么值得用」信任区 |
| P7 | **旗舰内容无展示位** | ❌ 最好的东西在哪？ | 东京 route-plan 路书（全站最强内容）在首页无入口位 |
| P8 | **无探索感/杂志感** | ❌ 有吸引力吗？ | 无大图叙事、无「查看全部」、无编辑语气 |
| P9 | **移动端长文字列表** | ❌ 手机上像样吗？ | 375px 单列文字卡一屏接一屏，无图片节奏 |
| P10 | **无搜索/筛选入口** | ❌ 直达目标内容？ | 无（v2.0 可先做「入口式」搜索，见 Part 2） |

**结论**：首页完成了「信息可达」，但没完成「3 秒说服」。它当前是一个**目录**，不是一个**入口**。

# 第二部分：首页 v2.0 信息架构

## 2.1 定位

> 首页不是内容列表，而是**「世界旅行规划入口」**：3 秒内让用户知道——这是一个国际旅行规划平台，能帮你从「想去哪」走到「怎么玩」，且值得信任。

## 2.2 页面结构（自上而下）

```
① Hero（品牌 + 口号 + 搜索入口 + 统计）
② Featured Destinations（精选目的地：国家 → 城市两级）
③ Popular Routes（热门路线，含旗舰路书 Featured）
④ Travel Planning Guides（旅行规划指南）
⑤ Seasonal Experiences（季节体验 / 最佳旅行时间）
⑥ Future Traveler Stories（未来用户故事 · 结构预留）
⑦ Footer（现有 v2.0，不动）
```

## 2.3 模块详设

### ① Hero
- **产品目的**：3 秒内建立「国际旅行规划平台」认知；给出唯一主动作。
- **用户心理**：第一屏需要「杂志级大图 + 简洁国际化口号」建立信任与向往；口号拆两行，先愿景（Explore the world.）后行动（Plan your journey.）。
- **展示内容**：
  - 全宽大图（沿用 `site.heroImage` unsplash，加深色渐变叠加提升文字对比度）；
  - 品牌 `Global Travel Guide`（衬线字标，与 Footer 呼应）；
  - 双行口号 **Explore the world. / Plan your journey.**（英文，国际化；中文可作副标）；
  - **Search destination**：视觉搜索框——输入后跳转 `/countries`（或 `/routes`），即「入口式搜索」；**真搜索（站点索引/联想）标注为 P3 能力**，本期不做功能；
  - **统计条 Stats Block**：国家 N · 城市 N · 路线 N（由 entities 自动派生，见 Part 5）。
- **数据来源**：`SITE.brand` / `site.heroImage` / home.json 新增可选字段 `heroTitle/heroLead`；统计由 `buildHomeSections(ctx)` 实体计数派生；文案常量可放 home.json。
- **是否 SEO 友好**：✅ 无新 URL；H1 唯一；口号/副标提升描述性；hero 文本可并入 JSON-LD WebSite.description；大图 alt 描述性。

### ② Featured Destinations
- **产品目的**：展示世界广度，引导「国家 → 城市」两级钻取。
- **用户心理**：用户带着「我想去哪」的模糊意图而来；大图卡帮助快速筛选；国家/城市两级视觉建立地理心智。
- **展示内容**：国家大卡（中国/日本：图 + 名称 + 副标）→ 其下城市小卡（北京/东京）；国家卡点击进 `/{country}/`，城市卡进 `/{country}/{city}/`。
- **数据来源**：`buildHomeSections` 的 destinations 拆分两组（countries / cities），按 `country` 关联；图用 `imageBaseUrl`（city/country JSON 新增可选 `image` 字段，R2 就绪）。
- **是否 SEO 友好**：✅ 内链全部指向现有 URL，传递内部权重；卡片 alt/文本描述性；不新增页面。

### ③ Popular Routes
- **产品目的**：把「规划」落地——给可执行的路线与路书。
- **用户心理**：确定目的地后，下一步是「怎么玩」；用户想要**可参考、有预算、有时间轴**的方案。
- **展示内容**：首屏位放**旗舰路书大卡 Featured Route-Plan**（东京经济版：封面图 + 「5 日经济版路书」+ 天数/预算徽标），其下路线卡（北京 3 日/5 日/适老、东京 3 日/5 日，带 `days` 徽标）；「查看全部」→ `/routes`。
- **数据来源**：`route-plans` + `routes` entities 自动派生；`days`/`suitableFor` 徽标取现有字段；北京遗留 static 路书暂不置顶（P1 吸收后并入）。
- **是否 SEO 友好**：✅ 内链 `/…/route-plan/economy`、`/…/routes/*` 现有 URL；路书是「可执行内容」，转化与收录价值最高。

### ④ Travel Planning Guides
- **产品目的**：提供工具性内容（交通/住宿/美食/预算），回答「怎么去 / 住哪 / 吃什么」。
- **用户心理**：规划中期的实用诉求；指南内容建立「编辑靠谱」的信任。
- **展示内容**：指南卡（按城市分组：北京交通/住宿/美食/贴士、东京交通/住宿/美食/预算）+「全球旅行指南」总入口 `/guides`。
- **数据来源**：`guides` entities 自动派生 + `/guides` 入口。
- **是否 SEO 友好**：✅ 指南页是长尾关键词主力（「北京美食攻略」等）；首页入口集中传递权重。

### ⑤ Seasonal Experiences
- **产品目的**：提供「几月去最好」的时间维度决策。
- **用户心理**：季节是高优先级筛选条件；「最佳季节」内容强化专业度。
- **展示内容**：季节卡（北京/东京最佳时间，带月份标签，如「9–10 月 · 秋高气爽」）。
- **数据来源**：`best-times` entities 自动派生。
- **是否 SEO 友好**：✅ best-time 页标题即长尾（「几月去北京最好」）；首页入口提升曝光。

### ⑥ Future Traveler Stories
- **产品目的**：为 v2.0 生态层（用户内容）预留首页位——**结构先行，数据后到**。
- **用户心理**：真实旅行者故事带来共鸣与社区感（小红书式心理）；现无数据不硬造。
- **展示内容**：空态模块「旅行故事即将到来 · Traveler stories coming soon」（复用 Empty State 组件），不渲染假内容。
- **数据来源**：无（P2 注册 note/photo/share/review type 后激活；authorship/engagement/tags 标准块见 Part 4）。
- **是否 SEO 友好**：✅ 空态不产生 URL、不参与索引，无重复内容风险；未来 UGC 页自带新增索引价值。

### ⑦ Footer
- 现有 v2.0 国际版（P0/P0.5 成果），**不动**。

# 第三部分：城市页 v2.0 信息架构

## 3.1 定位

> 城市页从「内容入口」升级为**「城市旅行主页」**：像一座城市的编辑部首页——一眼知道这座城、什么时候去、怎么玩、多少钱、有什么免费体验。

## 3.2 页面结构（自上而下）

```
① City Hero（城市名 + nameEn + 一句定位语 + 关键事实条）
② About City（城市简介 + 数据事实）
③ Best Time（最佳旅行时间摘要）
④ Featured Routes（热门路线 + 旗舰路书）
⑤ Budget Plans（预算方案）
⑥ Seasonal Guides（季节攻略）
⑦ Free Experiences（免费体验）
⑧ Traveler Content（未来用户内容 · 结构预留）
⑨ Related Cities（相关城市）
```

## 3.3 区域详设（数据结构 / 是否新增 type / 是否影响 URL）

| 区域 | 展示内容 | 数据结构 | 新增 type | 影响 URL |
|---|---|---|---|---|
| ① City Hero | 大图 hero + 城市名（北京 · Beijing）+ 定位语（如 Tokyo: *Tradition meets innovation.*）+ 事实条（大陆/语言/货币/时区，各取首 3 项） | city 增可选 `hero`(image key)/`tagline`；`nameEn/continent/language/currency/timezone` 已有（北京补齐） | **否** | **否** |
| ② About City | 简介段落（现 lead 扩展）+ 事实卡 | 现有 `lead/description`；city 增可选 `about`(blocks) | **否** | **否** |
| ③ Best Time | 最佳时间摘要卡（月份标签 + 一句结论），链接到 `/…/best-time` | 现有 `best-times` entity 派生；city 增可选 `bestTime`(摘要字符串) | **否** | **否** |
| ④ Featured Routes | 旗舰路书大卡（东京 economy；北京 normal/budget 待 P1 数据化）+ 路线卡 | 现有 `routes`/`route-plans` 按 country+city 过滤（`buildCitySections` 已支持）| **否** | **否** |
| ⑤ Budget Plans | 预算卡：东京 route-plan 已含 budgetTiers/budgetTable → 派生「经济版 ¥…」卡；北京 budget 静态页链接 | 复用 route-plan 预算模块；**P1 新增 `budget` type 时独立** | **P1**（设计期不注册） | **P1 时新增 `/…/budget/{slug}`（对旧静态 URL 评估 301）** |
| ⑥ Seasonal Guides | 季节攻略占位/摘要（未来 `seasonal` type 内容） | 现有 `best-times`；**P1 新增 `seasonal` type 骨架** | **P1** | **P1 时新增 `/…/seasonal/{slug}`** |
| ⑦ Free Experiences | 免费景点/体验精选（浅草寺、新宿御苑、上野公园等现有免费项） | attraction 增可选 `free`(bool)/`price`(string)；`buildCitySections` 派生过滤 | **否** | **否** |
| ⑧ Traveler Content | UGC 空态占位（结构先行） | **P2** 注册 note/photo/share/review + authorship/engagement/tags 标准块 | **P2** | **P2 时新增 `/…/notes|photos|shares|reviews/{slug}`** |
| ⑨ Related Cities | 同国其他城市卡（当前中国/日本各 1 城 → 空态；100+ 城市时自动） | 现有 `buildCountrySections` 同国城市派生；city 增可选 `relatedCities[]` | **否** | **否** |

> 设计期结论：**①–④⑦⑨ 全部可用现有数据模型 + 可选字段实现，零新 type、零 URL 变化**；⑤⑥⑧ 标记为 P1/P2 依赖，本次仅占位，不注册 type、不产生 URL。

# 第四部分：数据架构评估（100+ 城市扩展）

## 4.1 必须保持不动（架构资产，已验证优秀）

| 保持项 | 原因 |
|---|---|
| `urlFor / linkUrl` type 路由 | 新 type 只需加一个 case，零破坏 |
| `buildCitySections / buildCountrySections / buildIndexSections / buildHomeSections` 自动派生 | 加一个城市 JSON = 自动出现在城市页/国家页/目录页/首页，**零模板改动** |
| `buildBreadcrumb` 自动面包屑（JSON-LD） | 深层页位置感 |
| `blockInner`（section/notes/related 区块） | 内容渲染单一来源 |
| 模板引擎 `render.js`（零依赖纯函数） | Node / Worker 双端复用 |
| route-plan 12 模块模板 | 跨城市旗舰内容复用 |
| Design System 三件套 | 视觉单一来源 |

## 4.2 需要增加的字段（全部**可选、默认降级**，不破坏现有 46 页）

```jsonc
// city（可选新增，已有一半）
{
  "type": "city",
  "country": "china", "city": "beijing",
  "name": "北京", "nameEn": "Beijing",           // ✅ 已有（北京需补齐）
  "hero": "beijing-hero",                        // 🆕 卡片/hero 图 key（走 imageBaseUrl/R2）
  "tagline": "古都风韵，古今交织",                 // 🆕 一句定位语（City Hero）
  "highlights": ["故宫与长城", "胡同烟火", "烤鸭与京味"], // 🆕 3–5 个亮点

  "relatedCities": ["china-shanghai"],           // 🆕 相关城市（缺省自动派生同国城市）
  "about": [ { "kind": "section", "html": "…" } ], // 🆕 城市简介长文（可选）
  "continent": "亚洲", "language": "中文", "currency": "人民币 (CNY)", "timezone": "UTC+8", // ✅ 已有

// attraction（可选新增）

{ "hero": "china-hero", "highlights": [] }        // 🆕 国家卡图

// home（可选新增）

  "featuredRoutePlan": "japan-tokyo-economy" }     // 🆕 Hero/旗舰位配置

// UGC 标准块（P2）
{ "authorship": { "author": "", "avatar": "", "publishDate": "", "updateDate": "" },
  "engagement": { "likes": 0, "saves": 0, "comments": 0 }, "tags": [] }  // 🆕 P2 结构先行
```

## 4.3 结论

- **支持 100+ 城市：是**。核心机制（type 路由 + 自动派生）已验证可扩展到任意城市；本次设计新增字段全部可选、默认降级，现有 46 页渲染结果不变。
- 唯一结构性建议：`buildCitySections` 的 `groups` 数组后续可扩展（budget/seasonal/free 分组），同样零模板破坏。
- **不直接改代码**（本阶段约束）。

# 第五部分：Design System 组件需求

## 5.1 新组件清单（进入 `design-system`，禁止逐页写 CSS）

| 组件 | 用途 | 实现建议 |
|---|---|---|
| **Hero Component** `.hero` | 首页/城市页首屏：大图 + 渐变叠加 + 标题 + CTA + 统计 | 新 `hero.css`（引用 tokens；移动端限高） |
| **Stats Block** `.stats` | 国家/城市/路线计数条（首页） | 并入 hero.css 或独立 |
| **Destination Card** `.dest-card`（国家/城市两级变体） | 首页 Featured Destinations | 新 `cards.css` |
| **Route Card** `.route-card`（含路书大卡变体 `.route-card--featured`） | 首页/城市页热门路线 | 同上 |
| **Guide Card** `.guide-card` | 旅行指南 | 同上 |
| **Season Card** `.season-card`（月份标签） | 季节体验/最佳时间 | 同上 |
| **Section Header** `.section-head`（衬线标题 + 「查看全部 →」） | 各区块统一头 | 新 `sections.css` |
| **Badge/Tag** `.badge`（天数/版本/免费/月份） | 卡片徽标 | 复用/扩展现有 |
| **Empty State** `.empty` | Traveler Stories / Related Cities 占位 | 并入 cards.css |
| **Breadcrumb（可见）** `.breadcrumb` | 城市页/内容页可见面包屑（P0.5 遗留可选，纳入本设计） | 新 `breadcrumb.css` |

## 5.2 组织方式

- 建议在 `src/design-system/` 下新增 `home.css`（首页专属）与 `city.css`（城市页专属），二者仍**只引用 tokens/components 的 class**，共享通用组件（section-head/cards/badge）不重复定义。
- 严格原则：**任何页面不得新增私有 `<style>` 或私有 `:root` 颜色**；组件全部走 design-system。

> 严格「先架构后开发」；每阶段可独立上线、零破坏，且过验收（页面数 = 46、URL/canonical/sitemap 不变、无私有 CSS）。

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **A · 表现层重构（零新 type）** | 首页：新 `body-home.html` 模板 + Hero/统计/分组目的地/旗舰路书位/空态模块；城市页：hero + 分组渲染 + 可见面包屑；design-system 追加 hero/cards/section-head/badge/empty/breadcrumb 组件 | 无（纯模板 + CSS） |
