## 一、现状盘点（基于代码实测）

### 1.1 构建管线对静态页的处理
`scripts/build.js:236` 通过 `copyDir(STATIC_DIR, OUT_DIR)` 把 `src/static/**` **原样拷贝**到 `public/`，**不经过 `layout.html` 壳**。因此静态页自带 `<head>`、自带导航、自带 Footer，与 SSG 页（经 `renderPage`→`layout.html`）完全两套体系。

静态页清单（`src/static/`）：

| 文件 | 线上 URL | 类型 | 现状问题 |
|---|---|---|---|
| `about.html` | `/about` | 基础页 | 旧 `.topnav`(`.html`链接+`/china/beijing/`)、旧 Footer(邮箱/公司/SEO)、仅链 `style.css` |
| `services.html` | `/services` | 基础页 | 同上 |
| `contact.html` | `/contact` | 基础页 | 同上 |
| `privacy.html` | `/privacy` | 基础页 | 同上 |
| `terms.html` | `/terms` | 基础页 | 同上 |
| `sitemap-page.html` | `/sitemap-page` | 基础页 | 同上 |
| `china/beijing/budget.html` | `/china/beijing/budget` | 长表单路书 | **无 topnav**（仅旧 footer）、旧 Footer、私有 `:root` 配色 + 全屏 `.cover`、Chart.js、**未引用 design-system** |
| `china/beijing/normal.html` | `/china/beijing/normal` | 长表单路书 | 同上 |

> URL 校核：Cloudflare Pages 自动把 `about.html` 以 `/about` 提供（extensionless），故 canonical 用干净 URL 成立。静态页内部链接用 `.html` 仍可访问，但非规范形式 → 收口需统一为干净 URL。

### 1.2 八页共性缺陷（收口对象）
- **❌ 未接入 Design System**：8 页 `<head>` 均只 `<link href="/assets/css/style.css">`，**未引用** `/design-system/{tokens,components,responsive}.css`。
  - 后果：`style.css` 在 P0 已删除 `.site-footer` 规则 → **旧静态页 Footer 当前处于无样式状态**（裸 `<p>` 文本）；且缺失 `responsive.css`（`word-break:keep-all`、`html,body{overflow-x:hidden}`）与 tokens。
- **❌ 旧 Footer 内容**：6 基础页 + 2 itinerary 均含 `moming2603@hotmail.com`、`嘉兴市东诚信息咨询有限公司`、SEO 堆词段落、重复版权 —— 与 P0 已落地的国际版 Footer（删除邮箱/公司/SEO）**直接冲突**。
- **❌ 导航不一致**：
  - 6 基础页硬编码 `<nav class="topnav">`：首页 / 北京攻略(`/china/beijing/`) / 关于我们(`.html`) / 联系我们(`.html`) / 网站地图(`.html`) —— 与 SSG 导航（`site.json` 驱动、干净 URL）完全不同。
  - 2 itinerary **完全没有 topnav**，用户只能在页脚返回站点，导航断裂。

### 1.3 导航系统现状（SSG 侧）
- **来源**：`data/site.json` 的 `nav` 数组（7 项）→ `layout.html:28-32` `{{#each nav}}` → `.topnav` 药丸导航。
- **冗余（评估文档 P5）**：`目的地` 与 `国家` **均指向 `/countries`**，信息重复、不专业。
- **规则重复**：`.topnav` 同时在 `src/assets/css/style.css:16-34` 与 `src/design-system/components.css:9-27` 定义（值近似但双份，存在漂移风险）。
- **无可见面包屑**：`buildBreadcrumb`（`content.js:58`）仅输出到 JSON-LD，**页面不渲染可见面包屑**。
- **静态页与 SSG 页导航完全割裂**（见 1.2）。

## 三、P0.5 收口设计（目标态）

### 3.1 总原则
**表现层收口，不动数据模型 / `type` / URL / canonical / SEO。** 把 8 个静态页接入已建好的 Design System 壳：统一 `<head>` 链接、统一导航、统一 Footer、统一移动端规则。内容与文案一律不动。

### 3.2 每页动作（统一 4 步）
1. **`<head>` 注入**：在 `<link rel="stylesheet" href="/assets/css/style.css">` 之后，增加三行
   ```html
   <link rel="stylesheet" href="/design-system/tokens.css">
   <link rel="stylesheet" href="/design-system/components.css">
   <link rel="stylesheet" href="/design-system/responsive.css">
   ```
2. **导航统一**：
   - 基础 6 页：用**统一导航片段**替换原硬编码 `<nav class="topnav">…</nav>`。
   - itinerary 2 页：在 `<body>` 开头、`.cover` 之前**插入**统一导航片段（其自身无 nav）。
3. **Footer 统一**：用 **v2.0 国际版 Footer 片段**替换原旧 `<footer class="site-footer">…</footer>`（删除邮箱/公司/SEO）。
4. **链接规范化**：页内指向站内基础页的链接统一为干净 URL（`/about` 而非 `/about.html`）。

### 3.3 统一导航片段（单一来源，全站复用）
基于 `site.json` 去冗余后的导航（见第四节），HTML 结构即 `.topnav` 药丸栏：
```html
<nav class="topnav">
  <a href="/">首页</a>
  <a href="/countries">国家</a>
  <a href="/cities">城市</a>
  <a href="/attractions">景点</a>
  <a href="/routes">路线</a>
  <a href="/guides">旅行指南</a>
</nav>
```

### 3.4 统一 Footer 片段（v2.0 国际版，与 `layout.html:36-55` 完全一致）
```html
<footer class="site-footer">
  <div class="footer-brand">
    <span class="footer-logo">Global Travel Guide</span>
    <span class="footer-tag">Explore the world with smart travel planning.</span>
  </div>
  <nav class="footer-cols">
    <div class="footer-col">
      <h4>Explore</h4>
      <a href="/countries">Countries</a>
      <a href="/cities">Cities</a>
      <a href="/routes">Routes</a>
    </div>
    <div class="footer-col">
      <h4>About</h4>
      <a href="/about">About Us</a>
      <a href="/contact">Contact</a>
    </div>
  </nav>
  <p class="footer-copy">© 2026 Global Travel Guide</p>
</footer>
```

### 3.5 itinerary 特殊处理（不破坏其富样式）
- 其私有 `<style>`（含 `--primary`/`--bg-cream`/`.cover`/Chart.js）**全部保留**，仅补 design-system 链接 + 导航 + 换 Footer。
- `.cover` 全屏 hero 保持首屏；统一 `.topnav` 置于其前（非 sticky，与 SSG 一致）。
- 其 Chart.js、图片、文案一律不动。

## 四、导航系统重新设计

### 4.1 去冗余（修复 S4）
`data/site.json` 现 7 项含重复。收口为 **6 项干净导航**（删除重复的「目的地」，保留「国家」作为目的地入口）：
```
首页 /  ·  国家 /countries  ·  城市 /cities  ·  景点 /attractions  ·  路线 /routes  ·  旅行指南 /guides
```
> 安全：仅删菜单项，不删任何可达 URL（`/countries` 仍保留）。

### 4.2 单一来源（修复 S5）
- **删除** `src/assets/css/style.css` 中的 `.topnav` 块（第 16–34 行），由 `components.css` 作为唯一 `.topnav` 定义，消除双份漂移。
- SSG 页（`layout.html`）与静态页（3.3 片段）**共用同一套 HTML 结构与 class**，视觉一致。

### 4.3 可见面包屑（修复 S6，可选）
当前仅 JSON-LD 含面包屑。建议在城市 / 景点 / 路线 / 攻略 / 路书类 SSG 页**渲染可见面包屑**（数据已由 `buildBreadcrumb` 计算）：
```
首页 / 中国 / 北京 / 故宫
```
实现：在 `layout.html` `<main>` 顶部加 `{{#if breadcrumb}}<nav class="breadcrumb">…{{/each}}</nav>{{/if}}`，由 `renderPage` 注入。静态页如需面包屑可在收口中手工加（itinerary 可加「首页 / 中国 / 北京 / 路书」）。**此项为可选增强，默认先不做，避免改动 SSG 渲染链风险。**

### 4.4 响应式
`.topnav` 药丸栏在 `components.css` 已 `flex-wrap:wrap`，窄屏自动换行；`responsive.css` 已控 `overflow-x:hidden`。无需新增逻辑。

## 五、推荐实现方式（二选一，默认 A）

**方案 A — 直接编辑 8 个静态文件（推荐，轻量、零构建改动）**
- 逐文件做 §3.2 四步；改 `site.json` 导航去冗余；删 `style.css` 的 `.topnav` 块。
- 优点：不动 `build.js`、风险最低、URL/type 零影响。缺点：导航/footer 标记在 8 文件物理重复，未来改导航需改 8 处（可接受，静态页低频变更）。

**方案 B — 构建期注入（单一来源更彻底）**
- 在 `build.js` 的 `copyDir` 之后，对静态 HTML 做占位符替换（`<!--NAV-->`/`<!--FOOTER-->` → 统一片段）并注入 design-system 链接。
- 优点：导航/footer 真正单一来源。缺点：改动 `build.js`（需 HTML 解析/正则）、风险与复杂度更高。

> 鉴于约束"不破坏、轻量"，**推荐方案 A**。若用户追求长期单一来源可改 B。
